# REST Contract — Lab 05

The Lab 05 web client consumes **the same three endpoints defined in Lab 04**. No new endpoints were added for the interactive board (no `/moveElement`, `/drawRectangle`, `/connect`...): every add/move/connect/delete is applied to the local client state and persisted with a single `PUT` of the complete Board. The only contract evolution is in the **shape of `BoardElement`** (new `CONNECTOR` type plus `sourceId`/`targetId`).

| Method | Resource | Request | Success response | Error cases |
|---|---|---|---|---|
| POST | `/api/boards` | `{ "name": "string (required, non-blank)" }` | `201 Created` + Board body (`id` generated by the server, `elements` starts as `[]`) | `400` `INVALID_REQUEST` if `name` is blank/missing |
| GET | `/api/boards/{boardId}` | - | `200 OK` + Board body | `404` `BOARD_NOT_FOUND` if `boardId` does not exist |
| PUT | `/api/boards/{boardId}` | `{ "name": "string (required)", "elements": [BoardElement, ...] (required, may be empty) }` | `200 OK` + updated Board body (same `id` as before) | `404` `BOARD_NOT_FOUND` if `boardId` does not exist (does **not** create it); `400` `INVALID_REQUEST` if `name` is blank or `elements` is missing; `400` `INVALID_INPUT` if an element or connector invariant is violated (see below) |

## `Board` body shape

```json
{
  "id": "5048902c-5933-4b18-a827-c0d929db6452",
  "name": "Demo",
  "elements": [
    { "id": "r1", "type": "RECTANGLE", "x": 10.0,  "y": 10.0, "width": 100.0, "height": 50.0, "text": "API", "sourceId": null, "targetId": null },
    { "id": "t1", "type": "TEXT",      "x": 300.0, "y": 10.0, "width": 100.0, "height": 30.0, "text": "DB",  "sourceId": null, "targetId": null },
    { "id": "c1", "type": "CONNECTOR", "x": 0.0,   "y": 0.0,  "width": 0.0,   "height": 0.0,  "text": "",    "sourceId": "r1", "targetId": "t1" }
  ]
}
```

(Real response captured from `PUT /api/boards/{id}` against the running server.)

`elements[].type` is one of `RECTANGLE`, `TEXT`, `CONNECTOR`.

## Fields per element type

| Type | `x`/`y`/`width`/`height` | `text` | `sourceId`/`targetId` |
|---|---|---|---|
| `RECTANGLE` | Yes (position and size) | Optional (defaults to `""`) | **Must be absent/`null`** |
| `TEXT` | Yes | Yes | **Must be absent/`null`** |
| `CONNECTOR` | Not used for rendering (the server returns `0.0`; the client draws the line between the centers of source and target) | Not used (`""`) | **Both required** |

## Element and connector invariants

Validated in the domain (`BoardElement` and `Board` records), not in the controller. Each violation is rejected with `400 INVALID_INPUT`, the Board is **not** modified, and `message` explains which rule failed:

| Rule | Where it is enforced | Example `message` |
|---|---|---|
| Element `id` required and `type` required | `BoardElement` | `Element id is required` |
| `width`/`height` cannot be negative | `BoardElement` | `Element dimensions cannot be negative` |
| `CONNECTOR` requires `sourceId` | `BoardElement` | `Connector sourceId is required` |
| `CONNECTOR` requires `targetId` | `BoardElement` | `Connector targetId is required` |
| `sourceId` and `targetId` must be different | `BoardElement` | `Connector sourceId and targetId must be different` |
| Only `CONNECTOR` may define `sourceId`/`targetId` | `BoardElement` | `Only CONNECTOR elements may define sourceId/targetId` |
| Element ids must be unique within a Board | `Board` | `Duplicate element id: r1` |
| `sourceId`/`targetId` must reference an element that exists **in the same PUT** | `Board` | `Connector c1 references missing targetId: nope` |
| **A connector cannot connect connectors:** `sourceId`/`targetId` must reference a `RECTANGLE` or `TEXT`, never another `CONNECTOR` | `Board` | `Connector c2 cannot reference another connector` |

Because the PUT replaces the whole Board, "exists" means "is present in the `elements` array of that same request". If the client deletes an element, it must also delete the connectors that referenced it (the web client's `BoardState.removeSelected()` does this) or the save is rejected.

## Error contract

```json
{
  "timestamp": "2026-09-17T17:36:29.635470Z",
  "status": 400,
  "code": "INVALID_INPUT",
  "message": "Connector c2 cannot reference another connector",
  "path": "/api/boards/5048902c-5933-4b18-a827-c0d929db6452"
}
```

`code` values in use:

| `code` | Status | Origin |
|---|---|---|
| `BOARD_NOT_FOUND` | 404 | `BoardNotFoundException` thrown by `BoardApplicationService` |
| `INVALID_REQUEST` | 400 | Bean-validation failure on the request body (`@NotBlank name`, `@NotNull elements`) |
| `INVALID_INPUT` | 400 | A domain invariant rejected the input (`IllegalArgumentException` from `Board`/`BoardElement`, including every connector rule above) |
| `LAB_NOT_IMPLEMENTED` | 501 | Safety net for an unimplemented use case — should not fire in this delivery |

The web client (`BoardApiClient`) translates any non-2xx response into a `BoardApiError { status, code, message }` using these fields, so the view shows `message` without knowing about Java exceptions.

## Deviations from the reference starter and known limitations

- **`PUT` never creates a board implicitly.** Replacing a board that doesn't exist returns `404 BOARD_NOT_FOUND`; it is not an upsert (decision justified in `ADR-001-repository-boundary.md`).
- **The board `id` is always server-generated** (a UUID) on `POST`. Element ids (`rect-…`, `text-…`, `conn-…`) are generated by the client.
- **Extra rule vs. the lab guide:** the guide only requires connector endpoints to exist and be different. This delivery also rejects duplicate element ids and connectors pointing to other connectors, because the client draws a connector between the *centers* of two shapes, and a connector has no geometry of its own.
- **Known limitation:** a body that Jackson cannot parse at all (malformed JSON, or an unknown `type` such as `"CIRCLE"`) returns `400` with Spring's default error body (`{timestamp, status, error, path}`), not an `ApiError`, because `HttpMessageNotReadableException` is not mapped in `GlobalExceptionHandler`. The client's `BoardApiClient` still handles it (falls back to `code: HTTP_ERROR`). The web client never sends an unknown type.
